# Улучшение конспектов: глубина, таблицы, графики, UX

**Дата:** 2026-05-31
**Статус:** дизайн утверждён, готов к плану реализации
**Ветка:** feature/mvp

## Проблема

Конспект генерируется хорошо, но три ограничения снижают пользу:

1. **«Подробный» режим — фиктивный рычаг.** Единственное отличие
   `short / medium / detailed` — одна фраза в системном промпте
   (`SummaryService.php:70-74`). Число разделов, глубина, лимит вывода —
   одинаковые. `max_tokens` не задан вовсе, поэтому длина упирается в дефолт
   модели, а не в выбор пользователя.
2. **Нет структурированных сравнений.** Схема не просит таблиц, хотя рендерер
   (`Str::markdown` = GitHub-flavored) умеет их показывать из коробки.
3. **Числовые данные негде показать наглядно.** Mermaid рендерится в SVG, но
   используется только для flowchart/sequence — не для долей/динамики.

Плюс UX чтения: термины в тексте не связаны с глоссарием, нет акцента
«к экзамену», длинные подробные конспекты тяжело сканировать.

## Решение (обзор)

Подход к глубине — **один проход, усиленный** (без второго LLM-запроса):
богатые per-level инструкции + `max_tokens` по уровню. Схема `LectureSummary`
**не меняется** — всё ложится в существующие `content_markdown` (таблицы,
выноски) и `diagram_mermaid` (графики).

Среда подтверждена: Mermaid CLI **11.15.0** (поддерживает `pie` и
`xychart-beta`), CSS выносок в `resources/css/app.css`, таблиц в нём нет.

## Часть 1. «Подробный» как реальный рычаг

**Файл:** `app/Services/SummaryService.php`

Заменить однострочный `$detail` на развёрнутые per-level инструкции,
управляющие тремя осями:

| Ось | short | medium | detailed |
|---|---|---|---|
| Кол-во разделов | 3–5 | 5–8 | по числу смысловых тем, не экономить (≈8–14) |
| Глубина раздела | тезисы, главное | абзац + список | развёрнутые абзацы + пример + «почему важно» |
| Глоссарий | основные термины | средне | расширенный |
| Квиз | 3 | 3–5 | 5–7 |

Конкретные строки промпта (русский, в том же стиле, что и текущий):

- `short`: «Сжатый конспект: 3–5 разделов, только ключевые мысли тезисно.»
- `medium`: «Сбалансированный конспект: 5–8 разделов, по абзацу с пояснениями
  и списками.»
- `detailed`: «Подробный конспект: раскрой каждую смысловую тему отдельным
  разделом (не экономь на их числе). В каждом разделе — развёрнутое объяснение,
  конкретный пример и, где уместно, замечание «почему это важно». Глоссарий и
  вопросы для самопроверки — расширенные.»

**`max_tokens` по уровню.** Добавить в `config/services.php` карту лимитов и
передавать в запрос (`SummaryService::call`):

```php
// config/services.php → openrouter
'max_tokens' => [
    'short'    => env('OPENROUTER_MAXTOK_SHORT', 2500),
    'medium'   => env('OPENROUTER_MAXTOK_MEDIUM', 4500),
    'detailed' => env('OPENROUTER_MAXTOK_DETAILED', 9000),
],
```

`call()` сейчас принимает только `$messages`. Расширить сигнатуру, чтобы
передать выбранный `max_tokens` в тело запроса. Лимит выбирается по
`$options->detailLevel->value` в `summarize()`.

**Тесты:** проверить, что для каждого уровня в тело POST уходит корректный
`max_tokens` и соответствующая detail-инструкция (мок HTTP через
`Http::fake()`).

## Часть 2. Сравнительные таблицы

**Файлы:** `app/Services/SummaryService.php` (промпт),
`resources/css/app.css` (web), `resources/views/exports/pdf.blade.php` (PDF).

Рендеринг уже работает — нужны промпт + стили.

**Промпт.** Добавить пункт в блок «Дополнительно»:

> «Где в материале есть сравнение (методы, подходы, плюсы/минусы, классификация,
> хронология, параметры) — оформляй его Markdown-таблицей GFM. Пример:
> `| Критерий | Вариант A | Вариант B |` и строка-разделитель
> `| --- | --- | --- |`. Не злоупотребляй: таблица только там, где сравнение
> по >=2 параметрам действительно нагляднее текста.»

**CSS таблиц** — добавить в `app.css` в блок `.prose-content`:
рамки, чередование фона строк (`var(--inset)`), паддинги ячеек, жирный
заголовок, `overflow-x:auto` обёртка для узких экранов (mobile).

**PDF** — добавить `table/th/td` стили в `<style>` `pdf.blade.php`
(границы, `page-break-inside:avoid` для строк, фон шапки).

**Экспорты — поведение таблиц:**
- Markdown (`.md`): сохраняются как есть (билдер отдаёт `content_markdown`
  дословно — `SummaryMarkdownBuilder.php:21`). Без изменений.
- PDF: рендерятся как HTML-таблицы (через `ConspectusRenderer`). Нужен только CSS.
- DOCX: **известное ограничение** — `DocxExporter.php:38` делает
  `strip_tags(Str::markdown(...))`, таблица схлопнется в плоский текст.
  Полноценная таблица PhpWord = отдельный конвертер markdown→таблица.
  **Вне объёма этого захода**, помечаем как возможный follow-up. В тексте всё
  равно останется читаемо (значения через пробелы).

## Часть 3. Графики числовых данных (Mermaid)

**Файл:** `app/Services/SummaryService.php` (промпт). Без изменений кода
рендеринга — `DiagramRenderer` уже гонит любой Mermaid через `mmdc` в SVG/PNG,
а CLI 11.15.0 поддерживает `pie` и `xychart-beta`.

Графики работают только при включённом флаге диаграмм (`with_diagrams`), как и
сейчас — отдельного флага не вводим.

**Промпт.** Расширить инструкцию `diagram_mermaid` (сейчас только
graph/flowchart/sequence). Добавить:

> «Для числовых данных используй подходящий тип Mermaid:
> - доли целого → `pie` (`pie title ... \n "Метка" : 42`);
> - динамика/сравнение величин → `xychart-beta` (bar или line).
> Числа бери ТОЛЬКО из материала лекции, не выдумывай. Если точных данных нет —
> не строй график (diagram_mermaid = null).»

**Граничные случаи:** битый/невалидный Mermaid уже обрабатывается gracefully —
`DiagramRenderer::render` возвращает `null`, раздел рендерится без схемы
(`DiagramRenderer.php:41-43`). Дополнительной обработки не нужно.

**Риск галлюцинаций чисел** снижаем явной инструкцией «только из материала».
Принимаем остаточный риск (как и для остального содержания конспекта).

## Часть 4. UX чтения

### 4.1. Связь терминов с глоссарием

**Файл:** `resources/views/lectures/show.blade.php`.

- Глоссарий-карточкам (строки 169-174) дать `id="glos-{slug}"`, где
  `slug = Str::slug($term)`.
- Пилюли-термины раздела (строки 150-153): если нормализованный термин
  (`mb_strtolower(trim())`) совпадает с термином из глоссария — рендерить как
  `<a href="#glos-{slug}">` со скроллом (`scroll-mt-24` на карточках); иначе
  обычная пилюля без ссылки.
- Сопоставление строим один раз в начале блока готового конспекта
  (массив `term-normalized → slug`).

Только фронтенд, схема и данные не меняются. Низкий риск.

### 4.2. Акцент «К экзамену»

**Файлы:** `app/Support/ConspectusRenderer.php`, `resources/css/app.css`,
`resources/views/exports/pdf.blade.php`, `app/Services/SummaryService.php`.

- В `ConspectusRenderer::CALLOUTS` добавить тип:
  `'exam' => ['★', 'К экзамену', 'callout-exam']`.
- CSS `.callout-exam` в `app.css` (отдельный акцентный цвет, напр. фиолетовый
  через `color-mix`).
- В промпт — в список выносок добавить `> [!exam] ...` с пояснением:
  «то, что важно запомнить к экзамену/зачёту».

**Попутный фикс (PDF выноски).** В `pdf.blade.php` CSS-классы выносок названы
`.c-important/.c-note/.c-example/.c-tip`, а `ConspectusRenderer` отдаёт
`callout-important/...`. Из-за рассинхрона в PDF выноски сейчас без цветовой
типизации. Привести имена классов в `pdf.blade.php` к `callout-*` и добавить
`callout-exam`.

### 4.3. Прогрессивное раскрытие длинных разделов

**Файл:** `resources/views/lectures/show.blade.php` (Alpine.js + CSS, фронт).

Чтобы подробные конспекты было легче сканировать: раздел, контент которого
выше порога (напр. ~520px), сворачивается с градиентным fade и кнопкой
«Читать дальше ⌄» / «Свернуть ⌃». Реализация:

- Обёртка `prose-content` в `x-data="{ exp:false, tall:false }"`,
  `x-init` измеряет `scrollHeight` и ставит `tall=true`, если превышает порог.
- Если `tall && !exp` — `max-height` + `overflow:hidden` + fade-оверлей снизу.
- Кнопка тоггла показывается только при `tall`.
- Короткие разделы и весь контент при печати/экспорте — без изменений
  (логика только в web-вью; PDF/DOCX/MD не затрагиваются).

Дегенеративно: при выключенном JS контент виден полностью (max-height ставится
скриптом, по умолчанию класс не ограничивает высоту).

## Тестирование

- **Unit:** `SummaryService` с `Http::fake()` — на каждый уровень в теле запроса
  корректный `max_tokens` и detail-инструкция; промпт содержит инструкции по
  таблицам/графикам/выноскам.
- **Unit:** `ConspectusRenderer` — `> [!exam] ...` даёт `callout-exam` с меткой
  «К экзамену»; Markdown-таблица проходит в `<table>`.
- **Совместимость:** старые конспекты без новых элементов рендерятся как раньше
  (расширить существующий `LectureSummaryRichTest`).
- **Ручная проверка:** прогнать реальную лекцию в режиме «Подробно», глазами
  проверить web-вью и PDF (таблицы, график, выноска exam, раскрытие разделов).

## Принятые решения

- Глубина: один усиленный проход (не два LLM-запроса) — дёшево и без риска по
  таймаутам супервизора.
- Графики: внутри существующего флага `with_diagrams`, типы `pie`/`xychart-beta`.
- Таблицы в DOCX: осознанно отложены.
- Схема DTO не меняется — обратная совместимость со старыми конспектами.
